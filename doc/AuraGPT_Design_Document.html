Aura-GPT 系統設計與實作規劃

Draft

本頁是高階設計摘要。可執行規格以 doc/README.md 索引的 Markdown 文件為準；重大選型在實作驗證前均視為暫定。

1. 產品定位

Aura-GPT 是以本機大型語言模型為預設推論來源的桌面級 Web AI 助理。MVP 提供串流多輪對話、受控工具呼叫、白名單生成式 UI，以及可驗證的 GGUF 模型切換流程。

第一版聚焦單機、單使用者、單一載入模型。模型切換採「重新啟動並驗證」，不宣稱 hot swap，也不保證所有 GGUF 模型都支援工具呼叫。

2. 架構與責任

Browser / Next.js UI
        │  versioned stream events
        ▼
Chat API + bounded Agent loop ─── Tool registry ─── Local / external services
        │
        ▼
LLM adapter ─── verified OpenAI-compatible subset
        │
        ▼
llama-server ─── one configured GGUF model
元件主要責任
Next.js UI訊息、串流、取消、授權互動，以及白名單 UI component registry。
Chat API / Agent loop請求驗證、步數限制、工具協調、錯誤正規化與取消傳遞。
LLM adapter隔離 llama-server API、chat template 差異、model alias 與能力檢查。
Tool registry集中管理 schema、風險、授權、timeout、輸出限制與 UI mapping。
llama-server本機模型載入與推論，預設僅監聽 loopback。

3. 暫定技術方向

  • Next.js App Router 與 TypeScript；實作時鎖定已驗證版本。
  • Vercel AI SDK 負責 MVP 串流與有限步數 Agent loop。
  • Zod 作為工具、串流資料與 UI descriptor 的共用 schema 來源。
  • llama.cpp 的 llama-server 提供本機推論。
  • LangChain/LangGraph 暫不納入 MVP；出現持久化分支工作流或多 Agent 需求時再評估。

4. Agent 與工具規範

  • 每輪設定最大模型步數，避免無限 tool loop。
  • 所有工具必須具備 Zod schema、風險等級、timeout、輸出限制與公開錯誤 mapping。
  • 外部工具執行前揭露送出資料並依授權政策確認。
  • 唯讀且冪等的工具才可有限重試或平行執行。
  • 取消生成後不得再開始新的工具步驟。

5. Generative UI 安全模型

模型不得產生可執行 HTML、JavaScript 或任意 React。工具輸出經正規化後，只能建立帶版本的白名單 UI descriptor；伺服器與客戶端都必須驗證 props。未知元件、未知版本或渲染失敗時，降級為安全文字。

6. 模型與啟動管理

每個正式支援模型都需建立 profile，記錄來源、授權、SHA-256、量化、硬體需求、context、chat template、建議參數與 smoke test 結果。檔名不能作為相容性證明。

啟動流程必須先驗證工具鏈、模型與設定，再啟動 llama-server、等待 readiness、執行文字與工具 smoke test，最後啟動 Web 應用。Windows PowerShell 是 MVP 的必要支援路徑。

7. 隱私與安全

  • 未啟用外部工具時，對話內容不得由應用主動離開本機。
  • 模型輸出、工具輸入與外部回應一律視為不可信資料。
  • 工具權限由應用政策與使用者授權決定，不能交由模型自行判斷。
  • 預設 log 不保存完整 Prompt、回覆、秘密或未遮蔽個資。
  • MVP 僅允許 loopback；遠端存取需另行設計認證、TLS、CSRF 與 rate limit。

8. 分階段實作

  1. Phase 0：確認產品待決事項、鎖定工具鏈與建立首個模型 profile。
  2. Phase 1：完成可取消、可診斷的文字串流垂直切片。
  3. Phase 2：完成受控 Agent loop、正式唯讀工具與授權流程。
  4. Phase 3：完成版本化 Generative UI 與安全 fallback。
  5. Phase 4：完成模型 profile、啟動診斷、可觀測性與效能基準。
  6. Phase 5：通過整合、E2E、安全與模型相容性驗收。

9. 實作前待確認

  • 第一個正式工具。
  • 對話是否永久保存，以及位置與期限。
  • 外部工具採逐次、每工具或全域授權。
  • 第一個支援模型與目標硬體。
  • 是否提供 Docker Compose 作為第二種啟動方式。
