Aura GPT - 系統設計與架構規劃書

1. 專案概述 (Project Overview)

Aura GPT 是一款基於本地端大型語言模型 (Local LLM) 驅動的現代化 AI 代理系統。

本系統結合了靈活的 Web 介面與強大的本地端推論引擎，旨在提供高隱私性、低延遲的對話體驗。透過整合 Tool Calling (工具呼叫) 與 Generative UI (生成式介面)，Aura GPT 能夠突破本地模型的知識截斷限制，實現動態資料查詢與視覺化互動。

核心特色：具備「模型不可知 (Model-Agnostic)」特性，底層推論引擎可隨時無縫抽換為任意支援 Tool Calling 的 GGUF 模型，無需修改前端與代理層程式碼。

2. 系統架構 (System Architecture)

採用「前端介面、代理編排、本地推論」三層完全解耦的設計：

[ 用戶端 (Browser) ]
       │  ▲
       │  │ (HTTP Streaming / SSE 串流)
       ▼  │
[ 展示層: Next.js UI (useChat / Generative UI) ]
       │  ▲
       │  │ (傳送 Prompt + 工具結果 / 接收 Markdown 串流)
       ▼  │
[ 代理層: API Route + LangChain Agent ] ──▶ [ 外部 API (如天氣查詢) ]
       │  ▲
       │  │ (OpenAI REST API 格式: 帶入 tools schema)
       ▼  │
[ 推論層: llama-server (動態載入任意 GGUF 模型) ]

3. 技術選型 (Tech Stack)

層級 技術 / 框架 說明
前端與 API 層 Next.js 14+ (React) 負責 UI 渲染、路由管理與 API Route 處理
UI 與串流 SDK Vercel AI SDK (ai, @ai-sdk/react) 負責打字機效果 (Streaming)、Generative UI 渲染
Agent 編排層 LangChain.js, Zod 負責 Prompt 管理、Tool Calling 觸發與多輪對話控制
本地推論引擎 llama.cpp 以 llama-server 提供 OpenAI 相容 API

5. 模型動態抽換管理 (Model Swapping Management)

為了讓模型可以「任意抽換」，系統使用統一的環境變數進行控制，由啟動腳本讀取參數。

5.1 環境變數設定 (.env)

# --- LLM Server Configuration ---
# 只要更改這裡的檔名，就能一鍵抽換模型
LLM_MODEL_PATH=./models/qwen-3.7-instruct.gguf
LLM_SERVER_PORT=8080
LLM_CONTEXT_SIZE=8192
LLM_GPU_LAYERS=99

# --- Next.js Configuration ---
LLAMA_SERVER_URL=http://localhost:8080/v1

5.2 自動啟動腳本 (scripts/start-llm.sh)

#!/bin/bash
# 讀取 .env 檔案中的變數
export $(grep -v '^#' .env | xargs)

echo "🚀 啟動 Aura GPT 本地推論引擎..."
echo "📦 載入模型: $LLM_MODEL_PATH"
echo "🔌 服務埠口: $LLM_SERVER_PORT"
echo "🧠 上下文長度: $LLM_CONTEXT_SIZE"

# 啟動 llama-server
./llama-server \
  -m $LLM_MODEL_PATH \
  --port $LLM_SERVER_PORT \
  -c $LLM_CONTEXT_SIZE \
  --n-gpu-layers $LLM_GPU_LAYERS \
  --alias "aura-gpt-backend"

6. 核心功能實作規範 (Core Feature Specs)

  • 工具呼叫 (Tool Calling)： 所有註冊在 LangChain 的 Tools 必須以 Zod 定義 Schema。建議選用檔名帶有 Instruct 或 Tool 標籤的模型（如 Qwen-Instruct 或 Hermes）以確保 JSON 輸出穩定。
  • 無匹配處理 (Fallback)： 於 lib/agent/prompt.ts 設置防呆指令，若模型找不到合適工具，需自動降級為一般對話。
    「若使用者的請求無法透過現有工具解決，請勿虛構動作，直接使用你的預設知識回答，或誠實告知無法處理。」
  • 串流處理 (Streaming)： API Route 負責將 LangChain 的輸出轉為 Byte Stream，交由 Vercel AI SDK 解析並渲染打字機效果。
