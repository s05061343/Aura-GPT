# 產品需求

狀態：Draft

## 產品目標

JUNYX 是以本機大型語言模型為預設推論來源的桌面級 Web AI 助理。第一版要提供可串流的多輪對話、受控工具呼叫與預先定義的生成式 UI，同時讓使用者理解哪些資料留在本機、哪些資料可能被工具送往外部服務。

LangChain Python 是產品的核心 Agent 開發框架。模型存取、Prompt、工具註冊、多步執行與事件追蹤均透過 LangChain 邊界設計；UI 不直接編排工具。

## 目標使用者

- 希望在個人電腦執行模型，重視資料控制權的技術使用者。
- 需要以工具取得即時資料，但不希望整段對話預設上傳到雲端的使用者。
- 想抽換不同 GGUF 模型並比較能力的開發者。

## MVP 使用情境

1. 使用者啟動一個本機模型與 Web 介面並進行串流對話。
2. Agent 根據請求選擇已註冊工具，驗證參數後執行，再將結果交回模型整理。
3. 工具結果可用文字或白名單 UI 元件呈現。
4. 工具不適用、失敗或被拒絕時，系統給出可理解的降級回應。
5. 使用者可透過設定切換 GGUF 模型，重新啟動服務後生效。
6. 使用者能辨識本機處理與外部資料傳送的差別。

## MVP 範圍

### 包含

- 單機、單使用者、單一同時載入模型。
- Next.js 靜態 Web UI、Go 桌面 supervisor/gateway 與 FastAPI 本機 API。
- LangChain Python Agent runtime 與 llama-server model adapter。
- llama.cpp 提供的 OpenAI-compatible endpoint。
- 多輪對話、取消生成、Markdown 顯示及錯誤回饋。
- 至少一個唯讀示範工具，以及對應的生成式 UI 元件。
- 工具與模型相容性 smoke test。
- Windows 優先的啟動與診斷流程。

### 不包含

- 多租戶、帳號系統及跨裝置同步。
- 模型執行中 hot swap 或多模型自動路由。
- 模型任意產生或執行 HTML、JavaScript、Shell 或 SQL。
- 自主執行具金錢、刪除、發布或不可逆效果的工具。
- 保證所有 GGUF 模型都支援工具呼叫。
- 分散式部署與高可用性。

## 非功能需求

- 隱私：模型推論在本機；設定 LangSmith 金鑰時，完整 Agent trace 會預設上傳且 UI 必須揭露。天氣與股票工具仍需獨立授權。
- 安全：所有工具輸入都必須通過結構驗證與權限政策。
- 可恢復：推論或工具失敗不得造成聊天室整體崩潰，並允許重試。
- 可取消：使用者能停止生成，伺服器應中止下游請求。
- 可診斷：請求需有 correlation ID；LangSmith 有金鑰時保存完整 trace，無金鑰時本機日誌只記 metadata。
- 可替換：模型差異由設定與能力檢查處理，不滲入 UI 元件。

## 初期成功指標

- 支援清單中的模型能通過文字串流與工具呼叫 smoke test。
- 所有工具錯誤都有結構化錯誤事件與使用者可理解訊息。
- 未授權的外部工具不會執行。
- 中止生成後，不再繼續執行新的工具步驟。
- 新開發者只依文件即可完成啟動、測試及切換模型。

## 已確認產品決策

- 正式工具為 Open-Meteo 天氣與 TWSE／TPEx 最新官方收盤價。
- 對話不跨重新整理保存，記憶體 thread 閒置 30 分鐘清除。
- 外部工具採每個工具、每個分頁首次確認。
- 有 LangSmith 金鑰時預設上傳完整 Agent trace；無金鑰時安全降級。
- UI 採完整 AI 工作台資訊架構，包含可收合側欄、頂部執行狀態、starter prompts、對話區與整合式 composer。
- 尚未納入 MVP 的對話持久化／搜尋、帳號、附件與模型設定保留可辨識入口，但必須標示「待補」或 disabled；不得顯示假資料或暗示功能已可用。
